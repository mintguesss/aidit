- [x] **H1　開課資料依學校選取**
      排課、agent 的課程搜尋、對話裡用課名找課、課程資訊問答都限定學生自己的學校。
      用課號查詢的地方維持跨校（各校課號格式不重疊）。輔大 115-2 的 34 個開課班級已接上

      下學期是第 2 學期的學生永遠搜不到課；求解器沒擋同一門課選兩班。
- [ ] **H2　節次的顯示依學校**
      輔大代碼映射到內部整數節次，**內部 6 是輔大的 D5**。週課表、課表匯出（ICS 的鐘點）、

- [ ] **H3　輔大的示範學生**：合成學籍、真實規則，demo 才看得到輔大。等 C1 鎖版

## E. 資安

**在接真實學生資料之前，E1 到 E4 全部都要做完。** 現在是合成資料所以無害，
但這幾條都不是「加強」，是「缺」。

- [ ] **E1　身分驗證**
      現在**完全沒有**：沒有 middleware，沒有 session，沒有任何登入。
      自架的那台在做出來之前只能待在 Tailscale 內網，不要 port forwarding。
      **而且要明確綁 Tailscale 位址**：`next start` 沒給 `-H` 時綁所有網卡，不是 127.0.0.1
      （[SELFHOST.md](SELFHOST.md) §二）。
- [ ] **E2　`/api/review` 加驗證或限制到內部網段**
      這是內部作業端點，能鎖規則包版本 —— 鎖錯版等於所有人的判定依據都換掉。
      端點自己的註解就寫了這件事。
- [ ] **E3　`/api/preferences` 的身分是請求參數決定的**
      [route.ts](../src/app/api/preferences/route.ts) 的 `identify()` 從 body 裡的
      `fixture` 推出學生，沒有任何驗證。也就是說**任何人都能讀、寫、刪掉
      指定學生的偏好，`scope=all` 還會連執行紀錄一起刪**。
      合成資料下無害，接真實資料就是嚴重漏洞。根因是 A2。
- [ ] **E4　上傳檔案只看副檔名**
      `/api/rulepack` 用 `name.endsWith(".pdf")` 判型別，沒檢查 magic bytes。
      大小上限有做。
- [ ] **E5　API 速率限制**
      特別是會呼叫模型的 `/api/chat` 與 `/api/whatif` —— 沒有限制的話，
      一個迴圈就能把額度跑完。單輪 LLM 呼叫上限只擋單次請求，不擋請求數。
- [ ] **E6　安全標頭**
      [next.config.ts](../next.config.ts) 目前只設了 `/api/*` 的 `Cache-Control`。
      缺 CSP、`X-Content-Type-Options`、`Referrer-Policy`、HSTS。
- [ ] **E7　`service_role` key 的權限面過大**
      所有路徑都用同一把繞過 RLS 的鑰匙。之後可以分出受限角色，
      讓查詢類端點拿不到刪除權。
- [ ] **E8　執行期的去識別驗證**
      CI 第 6 項掃的是**原始碼**。沒有任何測試驗證「實際產生的 trace 裡
      不含姓名或學號」。那是 SPEC §9 的硬要求，應該有不變式擋著。
- [ ] **E9　相依套件稽核進 CI**
      `npm audit` 目前沒有跑。
- [ ] **E10　`AIDIT_TRACE_SECRET` 的輪替程序**
      換密鑰會讓舊 trace 的 `student_hash` 全部對不上 —— 那些紀錄不是消失，
      是再也連不回學生，「刪除我的資料」對換密鑰前的紀錄會失效。
      要換就趁還沒有真實資料時換，或先想好遷移方式。

## G. 對話與排課

- [ ] **G1　課表微調可以指定每門課的學分數**
      使用者會說「多選一堂兩學分的課」「只想修三學分的課」。現在做不到：
      堂數照加，學分數不處理，回覆明講「目前還不能指定每門課要幾學分，這部分沒有套用」
      （[route.ts](../src/lib/chat/route.ts) 的 `unsupportedAsks()`）。
      要做的是：意圖 schema 加欄位、[apply.ts](../src/lib/chat/apply.ts) 套用時照樣要求
      數字對得上原句、求解器支援、離線規則接得住。
      **先決定語意**：是硬限制（只准 N 學分的課，湊不到就回報做不到），還是偏好
      （盡量挑 N 學分，挑不到照排並說明）？「多選一堂 N 學分」只限制新加的那一門，
      還是整份課表？
      注意「N 學分的課」不能被當成學期學分上限 —— 現在靠 `CREDIT_CAP_CUE` 擋著，
      改的時候別弄掉。做完要一併更新 [chat.test.ts](../tests/chat.test.ts) 裡
      「兩學分的課」那條測試，以及 [chat-e2e.mjs](../scripts/chat-e2e.mjs) 的
      「多選一堂兩學分的課」，兩者現在都在檢查「沒有套用」那句話。
- [ ] **G2　課表微調不能用關鍵字找課**
      「有沒有程式相關的課」在課表微調介面只能回查無 —— 它只認得課名，不會搜尋。
      修業問答那一側查得到。要不要讓兩側共用查詢，還是明講去修業問答問。
- [ ] **G3　超出範圍的拒絕理由有時套錯類**
      「今天天氣如何」qwen 會拒絕，但套用的是「他校事務」的說法與承辦單位；
      離線規則回的是一般的超出範圍。規則只在自己判定為**禁止主題**時才更正理由，
      這句規則判的是「超出範圍」，所以不介入。影響小，但理由決定轉介到哪裡。
