# Aidit 系統文件

修業規劃與畢業審查輔助系統。本文件整合系統的設計、架構、安裝、操作、資料、安全與維運，
給接手開發、部署維運、評審查核的人看。細節以 repo 內各專題文件為準（第 20 章索引）。

文件版本：2026-10-08　程式版本：main 分支（v0.1.0）

---

## 1. 系統概述

### 1.1 解決的問題

大學部學生每學期選課前，要自己對照「課程規劃表」「修業規則」與歷年公告，逐門判斷已修課程算進哪一類、
每一類還差幾學分，再從數百班開課資料中排出不衝堂、選得到的課表。規定分散、有未寫明之處，
總學分夠了卻因某一類不足而無法畢業的情況，常到大四才發現。

### 1.2 系統做什麼

- 讀取修課紀錄，依入學年度綁定適用的規則版本
- 逐類別比對畢業學分，每條結論附原文出處
- 偵測可能改變規定的公告，查證是否適用該學生；判斷不了就轉人工
- 依未修學分、開課資料與學生條件，求解下學期課表
- 情境試算：提前畢業、停修、下學期修某一門課等
- 兩個對話入口：調整課表、修業問答
- 完整執行紀錄（trace），可供查核

### 1.3 刻意不做的事

不代為選課、不寫回任何校務系統、不儲存帳密或代為登入、不預測成績或被當機率、不對教師作評價、不大量爬取論壇。

### 1.4 核心主張

**在畢業審查場域，答錯的代價遠高於不答。** 系統以零錯答為優化目標，接受較高的轉人工率。

## 2. 設計原則

| 原則 | 落實方式 |
|---|---|
| 算數的那層沒有模型 | 學分審查、課表求解、原文回查為確定性程式；CI 第 4 項做遞移相依分析，任一層引用模型呼叫即建置失敗 |
| 不變式失敗就中止 | `可採計 + 修課中 + 未修 = 畢業最低學分`、`已修得 = 可採計 + 超修`；不成立即中止，不輸出結果 |
| 每條結論可回查原文 | 規則包每個欄位帶原文引句；輸出前回查（精確 → 模糊 ≥ 0.90，數字須完全一致），對不上重試一次，仍失敗則降級為待確認 |
| 對話的每一個字都不是模型寫的 | 模型只輸出意圖與參數（schema 無回答欄位），回覆由模板依引擎輸出組成 |
| 不確定是資料驅動的 | 規則缺口寫在規則包（ambiguity）與公告庫（effect），命中的課移出採計並產生待確認事項 |
| 外部內容是資料不是指令 | 公告原文交給模型前先過注入掃描，命中即不送、轉人工 |
| 高風險留給人 | 規則包須人工逐條校對才能鎖版生效；畢業資格一律標示「參考，非證明」 |

## 3. 系統架構

### 3.1 分層

| 層 | 內容 |
|---|---|
| 介面 | Next.js App Router 頁面：首頁（審查報表）、修業明細、待確認、選課建議、修業問答、情境試算、資料來源、執行紀錄、規則校對、課程大綱 |
| API | `src/app/api/*`，Node.js runtime（第 15 章） |
| Agent 執行器 | `src/lib/agent/runner.ts`：自寫 step runner，每一步寫 trace；刻意不用 agent 框架（流程有限且已知，trace 格式自行控制） |
| 確定性核心 | 審查引擎 `src/lib/audit/engine.ts`、指派 `assign.ts`、求解器 `src/lib/solver/schedule.ts`、原文回查 `src/lib/verify/citation.ts` |
| 模型層 | `src/lib/llm/client.ts`：結構化輸出（zod schema 驗證）、每輪呼叫上限、逾時與預算；無金鑰時走確定性替身 |
| 對話 | `src/lib/chat/*`：意圖解析 → 條件合併 → 重新求解 → 模板回覆 |
| 資料 | 規則包、公告庫、原文語料、開課資料、課程大綱、偏好、trace（第 6 章） |
| 儲存 | Supabase（Postgres）；未設定時以 `.data/` 檔案替身，介面相同 |

### 3.2 技術選型

Next.js 15（App Router）＋ React 19 ＋ TypeScript、Tailwind CSS、Supabase、Vercel；求解器自寫分支定界；測試 Vitest。

## 4. Agent 任務流程

### 4.1 審查流程（8 步）

| # | 步驟 | 工具 | 失敗或分支 |
|---|---|---|---|
| 1 | 讀取修課紀錄 | `record.fetch` | 失敗 → 中止 |
| 2 | 綁定規則版本 | `rule.resolve` | 學籍入學學年與實際不符 → 整案轉人工；規則包未鎖版 → 不判定 |
| 3 | 比對公告庫 | `rule.conflict` | 找出可能改變規定的公告（限定學校、系所、組別） |
| 4 | 查證公告是否適用 | `safety.scan`、`rule.reconcile`（模型） | 原文命中注入樣式 → 不送模型、轉人工；判斷不了 → 待確認；適用且有效果 → 本次審查用的規則包加入規則缺口 |
| 5 | 學分審查 | `credit.audit`（不經模型） | 不變式不成立 → 中止 |
| 6 | 原文回查 | `citation.verify` | 對不上 → 重試 1 次 → 降級為待確認 |
| 7 | 查下學期開課 | `course.search` | 查無 → 只出審查結果，略過排課 |
| 8 | 求解課表 | `schedule.solve` | 無解 → 找出衝突條件 → 放寬重試 → 仍無解則說明原因 |

### 4.2 真實例子

學校全人教育課程中心 114-1 公告同時規定兩種入學年度。系統拆成兩則判斷：
「114 學年起新通識架構」對 111 入學生**不適用**，仍照原規劃表；
「113 學年（含）前入學生修永續素養領域的課，依抵認對照表認定」**適用** → 學生修了這類課，該課移出採計、
列為待確認（附公告原句、已查來源、承辦單位），排課也不拿這類課湊通識。

### 4.3 對話流程

使用者一句話 → 模型（或離線規則）解析成結構化條件 → 驗證參數必須在原句有依據 → 與目前條件合併 →
重新求解 → 回報「改了什麼、課表差異、代價」，做不到的部分明講沒有套用。每輪寫 trace。

## 6. 資料與資料流程

### 6.1 資料盤點

| 資料 | 位置 | 保留 | 個資 |
|---|---|---|---|
| 修課紀錄 | 每次重讀，不寫出 | 單次請求 | 含學號但不落地 |
| 偏好、畢業條件自行勾選 | Supabase `preferences` | 12 個月未用即刪 | 以 HMAC 雜湊識別 |
| 執行紀錄 trace | Supabase 或 `.data/traces/` | 90 天 | 雜湊識別，輸入輸出遮罩 |
| 課表 | 不存，每次重算；可匯出 ICS／CSV | — | — |
| 規則包 | 鎖版者在 Supabase `rule_packs`；草稿在 `rulepack_drafts` 與 `docs/review/` | — | 無 |
| 原文語料 | `src/lib/rules/corpus/*.txt` | — | 公開文件 |
| 開課資料 | Supabase `offerings`（優先）；repo `src/lib/offerings/data/` 為離線基準 | — | 公開資料 |
| 課程大綱 | 不存，開啟時向學校大綱系統即時查詢，快取一天 | — | 不收教師聯絡方式 |
| 示範學生 | `src/lib/providers/fixtures*.ts` | — | 真實成績單只取課名、學分、學期、及格與否，經本人同意 |

### 6.2 規則包資料流

官方 PDF → 分段文字（保留頁碼）→ 抽取草稿（每欄位附原文引句）→ 自動驗證（schema、學分加總、引文回查）→
上傳草稿 → 校對頁逐條人工確認或修改 → 全部通過後鎖版 → 發布到 `rule_packs` → 審查使用。

### 6.3 開課資料流

學校公開課程查詢 API 抓取（每次請求間隔 2 秒，User-Agent 只寫專案網址）→ 轉換為系統格式（選別、時段、開課班級、
年級、通識領域）→ 上傳資料庫，網站十分鐘內載入，不用重新部署。類別於執行期依學生的規則包判斷。

### 6.4 審查請求的資料流

學生選定 → 讀修課紀錄 → 綁定規則包 → 公告查證 → 審查 → 回查 → 開課 → 排課 → 回傳結果並寫 trace。
修課紀錄不寫出；trace 只存去識別內容。

## 7. 規則包與人工校對

- 規則包內容：畢業最低學分、類別（課號清單、課名、選別、本系選修、任何及格課）、附加條件（通識領域學分、本系選修下限、指定課程門數）、
  規則缺口、超修政策、畢業條件（佐證、各系自訂、修過指定課）、全學年課程、學期學分上下限、文件出處。
- 同系不同組可各有規則包（以組別區分）。
- 校對頁（`/review/<規則包代號>`）：每一項以白話描述系統的理解，旁列原文並高亮依據，校對人逐項「通過／需要修正／退回」。
  修正直接在表單上改，存檔時跑同一套自動驗證並留修改紀錄。全部通過才能鎖版。
- 校對要先登入（`/review/login`，姓名＋校對密碼），登入 12 小時有效；校對紀錄以登入的姓名記錄校對人。

目前收錄：試辦學系 111 學年（v0.7 校對中，線上使用已鎖版的 v0.6）、第二個學系的一個組 112 學年（v0.1 草稿，待校對）、合成學校（評測基準）。

## 9. 安全、權限與治理

### 9.1 權限

| 對象 | 權限 |
|---|---|
| 學生（使用者） | 讀自己的審查結果、調整課表、試算、設定偏好、刪除自己的偏好資料 |
| 校對人 | 以姓名＋校對密碼登入後，對草稿逐項校對、修改、鎖版 |
| 維運者 | 持有 Supabase service role key（只放伺服器環境變數），上傳開課資料與草稿 |
| 系統 | 不能寫回任何校務系統；沒有登入學校系統的程式 |

### 9.2 防護

- 速率限制：會呼叫模型的端點每 IP 每分鐘 15 次，其他寫入端點 30 次；自架時另有全體合計上限
- 安全標頭：CSP、HSTS 等（`next.config.ts`）
- 上傳檔案檢查 PDF 檔頭
- 注入掃描 9 種樣式；外部內容不參與學分計算
- 拒答六類：成績預測、被當機率、教師評價、代為選課、代為送件、違規繞過
- CI 第 6 項檢查原始碼不得含金鑰或真實學號

### 9.3 失敗處理

中止（不變式、讀取失敗）、整案轉人工（學籍不符）、單項降級待確認（回查失敗、規則缺口、公告判斷不了）、
放寬重試（排課無解）。模型逾時或輸出不合 schema 時改用確定性規則解析，仍不明確就反問，不猜。

## 11. 安裝與執行

### 11.1 需求

Node.js 20 以上、npm；選用：Python 3.9 以上（資料抓取與文件轉換腳本，需 `pdfplumber`、`python-docx`）、Supabase 專案、模型端點。

### 11.2 本機執行

```
git clone <repo>
cd aidit
npm install
cp .env.example .env       # 依第 14 章填寫；全部留空也能跑（離線模式、檔案替身）
npm run dev                # http://localhost:3000
```

### 11.3 檢查

```
npm run ci                 # 7 項 CI 檢查
npm test                   # 自動化測試
npm run eval               # 評測報告
npm run build && npm start # 正式建置
```

### 11.4 資料庫

在 Supabase 依序執行 `supabase/migrations/0001`～`0004`，設定 `SUPABASE_URL` 與 `SUPABASE_SERVICE_ROLE_KEY`。

### 11.5 常用維運指令

| 目的 | 指令 |
|---|---|
| 抓一學期開課資料 | `python scripts/fju-sis-fetch.py 115 1` |
| 轉換開課資料 | `python scripts/fju-sis-offerings.py 115 1 <規則包草稿> src/lib/offerings/data/fju-115-1.json` |
| 上傳開課資料 | `npx tsx scripts/push-offerings.ts <檔案> "<來源>"` |
| 驗證規則包 | `npx tsx scripts/validate-rulepack.ts <草稿>` |
| 上傳草稿供校對 | `npx tsx scripts/push-draft.ts <草稿>` |
| 成績單課名查課號 | `python scripts/fju-sis-lookup.py <輸入> <輸出>` |
| 競賽文件轉 Word | `python scripts/competition-docx.py` |

| `AIDIT_TRACE_SECRET` | 正式部署必填 | trace 去識別用的 HMAC 密鑰；各部署用同一組 |
| `AIDIT_REVIEW_PASSWORD` | 選填 | 校對密碼；未設定時用程式內建的預設值（暫時做法，正式使用前須設定） |
| `AIDIT_DATA_DIR` | Vercel 必填 `/tmp/aidit` | 檔案替身位置 |
| `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` | 選填（兩者皆設才啟用） | service role key 只能放伺服器端，不得加 `NEXT_PUBLIC_` 前綴 |
| `ANTHROPIC_API_KEY` | 選填 | 未設定則模型呼叫走替身 |
| `AIDIT_LLM_PROVIDER` | 選填 | `anthropic`（預設）或 `openai-compatible` |
| `AIDIT_LLM_MODEL` | 選填 | 模型名稱 |
| `AIDIT_LLM_BASE_URL`、`AIDIT_LLM_API_KEY` | openai-compatible 用 | 端點與金鑰 |
| `AIDIT_LLM_TIMEOUT_MS` | 選填 | 預設 anthropic 8000、openai-compatible 30000 |
| `AIDIT_LLM_REASONING_EFFORT` | 選填 | 思考型模型填 `none` |

所有密鑰只放環境變數，不進程式碼與文件。

## 15. API

所有端點在 `/api` 下，JSON 格式。寫入端點受速率限制。

| 方法與路徑 | 用途 |
|---|---|
| `POST /api/audit` | 執行審查，回傳結果與 trace 編號 |
| `POST /api/plan` | 依選課傾向產生課表 |
| `POST /api/whatif` | 情境試算 |
| `POST /api/chat` | 調整課表、修業問答（兩個對話共用） |
| `POST /api/extra-goals` | 額外修業目標（輔系、學程）修課現況 |
| `POST /api/declarations` | 畢業條件自行勾選 |
| `POST`／`DELETE /api/preferences` | 選課偏好；刪除自己的資料 |
| `POST /api/rulepack` | 上傳規則包 JSON 或規劃表 PDF（不會直接生效） |
| `POST /api/review` | 校對寫入與鎖版（需校對密碼） |
| `GET /api/trace/:id` | 取回執行紀錄 |
| `GET /api/corpus/:docId` | 原文回查 |
| `GET /api/offering/:code` | 開課資料（原始列與正規化結果） |
| `GET /api/anon-terms` | 匿名展示模式的教師名單 |
| `GET /api/health` | 健康檢查 |

完整參數見 `docs/API.md`。

## 17. 已知限制

- 真實規則目前兩個學系（各一個入學年度）；輔系、學分學程規則未收錄，試算時明講未收錄
- 評測以合成資料為主；真實資料有測試但尚未整理成指標表；人工計算、單次模型基準待實測
- 公開 demo 不接模型；接 Claude API 尚未實測（延遲、成本、注入）
- 開課資料沒有已選人數，餘額一律顯示未知；先修條件信心低時只提示不排除
- 排課搜尋有節點上限，撞到時標示「可行但不保證最好」
- 對話找主題課（例如「AI 相關」）只比對課名，課名沒寫到的相關課會漏
- 速率限制計數在記憶體，多個執行個體各算各的
- 校對密碼未設環境變數時使用程式內建預設值（只存雜湊），正式使用前須設定
- 匿名展示模式只改顯示層；點開的原始文件連結仍是學校網站

## 18. 故障排除

| 症狀 | 原因與處理 |
|---|---|
| 頁面顯示「尚未支援此系所／學年度」 | 找不到同系、同組、同入學年度的規則包，或沒接 Supabase 讀不到已鎖版的規則包 |
| 顯示規則包未核可 | 規則包仍是草稿，須在校對頁全部通過並鎖版 |
| Vercel 上 trace、偏好、校對寫入失敗 | `AIDIT_DATA_DIR` 未設為 `/tmp/aidit`（serverless 專案目錄唯讀） |
| 打開校對頁被帶到登入頁 | 校對要登入；登入 12 小時有效，換了校對密碼後舊的登入會失效 |
| 開課資料改了網站沒變 | 資料庫版本優先於 repo 版本：用 `push-offerings.ts` 上傳；網站十分鐘內載入 |
| API 回 429 | 觸發速率限制，依 `Retry-After` 秒數後再試 |
| 自架模型回應很慢或逾時 | 思考型模型設 `AIDIT_LLM_REASONING_EFFORT=none`，或調高 `AIDIT_LLM_TIMEOUT_MS` |
| trace 顯示 `mode=offline` | 沒有可用的模型設定，走確定性替身；屬預期行為 |
| 公告判斷顯示「含疑似指令的文字」 | 注入掃描命中；確認是否誤攔，誤攔要把該句加進注入測試語料的正常樣本並調整樣式 |
| 排課結果附「搜尋空間過大」 | 撞到節點上限；結果可行但不保證最好，可加條件縮小範圍 |
| CI 第 4 項失敗 | 判定層引用了模型呼叫；把呼叫移出審查、求解、回查三個模組 |
| CI 第 6 項失敗 | 原始碼出現疑似金鑰或學號；移除，若是誤判加入允許清單 |

## 19. 開發規範

- 改動前先跑 `npm run ci`；新增功能須附測試
- 判定層（審查、求解、回查）不得呼叫模型
- 規則改動走「改草稿 → 驗證 → 上傳 → 校對 → 鎖版」，不直接改線上規則包
- 真實學生資料不進 repo；密鑰只放環境變數
- 與規格不一致之處逐項記入 `docs/SPEC-CHANGES.md`
